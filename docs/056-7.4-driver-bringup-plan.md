## 2. 阶段路线图

### P0 — 7.4 首次真机 bring-up（先验证，不移植新驱动）

目前**没有任何 7.4 真机 probe 日志**：`TMP/` 下的日志全是 6.3 backport 版本。先确认 7.4 自身可用。

1. 用最新 7.4 release 的 recovery-flasher 包刷机（p2/p5/p6/p8，p1 不写）。
2. 按 `docs/053` 分层记录：**L0** 启动/logo/绿带 → **L1** 串口或 framebuffer TTY 文字 → **L2** 路由器上的新 IP / SSH。
3. 采集判据：`uname -r`（应为 `7.4.0-rc2`）、`dmesg` 中 `histb-vdp`/`lima`/`sii9134` 的 probe 行、`cat /proc/cmdline`（含 `root=/dev/mmcblk0p8`、`cma=160M`）、`grep CmaTotal /proc/meminfo`、`ls /dev/dri*`、挂载点与 `/sys/class/thermal`。
4. 结果写入新验证日志（建议 `docs/057-7.4-hw-verify-log.md`），**一次只改一个变量**。

**完成标准**：L0+L1+L2 全绿，`CmaTotal=163840 kB`，`/dev/dri/card0`(VDP) 与 `renderD128`(lima) 存在。

### P1 — 显示链路收敛（KMS → fbdev → X/glamor）

1. `modetest -M histb-vdp` 列 connector/mode，确认 SiI9134 bridge probe 与 EDID 读取。
2. 排查 `fbdev: Failed to setup generic emulation (ret=-12)`：本质是 CMA/显存池不足或 fbdev 与 KMS 抢占；先确认 `cma=160M` 真正生效，再决定是否调整 `media_cma` 或 `drm_fbdev_generic_setup` 的 bpp。
3. 排查 `i2c i2c-0: of_i2c: modalias failure on .../hdmi@8ce0000/ports`：该节点刻意不设 `ddc-i2c-bus`（EDID 由发射器自读），非致命；若影响 bridge 注册，给 ports 节点加 `status`/`compatible` 修正补丁。
4. 处理 X11：`modesetting` 必须选 VDP 的 KMS card，kmsro shim `histb_vdp_dri.so` 必须被 DRI3/PRIME 加载；目标是 `glxinfo` 显示 `Mali450` 而非 `llvmpipe`。
5. 严禁回退到用户态 mmap fb0。

**完成标准**：HDMI 有稳定画面；`modetest` 有 connector；Xorg glamor 初始化成功；`glxinfo | grep OpenGL renderer` = Mali450；连续运行 30 分钟不死机。

### P2 — 补齐 config 缺口（成本最低的"驱动移植"）

补丁和 DT 节点都已在 `patches/histb/` 中，缺的只是 config 启用 + 断言。在 `configs/kernel/ec6108v9c.config` 显式加入，并在 `scripts/build-kernel.sh` 的硬断言列表里补齐：

```
CONFIG_VIDEO_HISTB_VDEC=y
CONFIG_VIDEO_HISTB_VENC=y
CONFIG_VIDEO_HISTB_VPSS=y
CONFIG_VIDEO_HISTB_JPGD=y
CONFIG_VIDEO_HISTB_JPGE=y
CONFIG_SND_SOC_HISTB_AIAO_I2S=y
CONFIG_SND_SOC_HISTB_AIAO_CARD=y
CONFIG_SND_SOC_HISTB_ADAC=y
CONFIG_AMBA_PL08X=y
CONFIG_PINCTRL_SINGLE=y
CONFIG_REGULATOR_HISI_STB=y
```

（符号名已逐一对过补丁中的 `config` 定义与 `TMP/gthifb-config/02-select-y.txt`。）

验证：`/dev/video*` 出现、`v4l2-ctl --list-formats-out`、`arecord -l` / `/proc/asound/cards` 有 hi3798mv100-aiao-card；IR 用 `ir-keytable -t` 录键后补板级 keymap 补丁。

**完成标准**：上述符号在 `olddefconfig` 后仍为 `y`（靠 build 断言保证）；`/dev/video*` 与声卡节点存在；遥控按键能映射成实际键码。

### P3 — 稳定性收尾

- thermal：7.4 的 CRG/regulator/DTS 已修正区间重叠，确认温区与被动/临界温度生效（85°C/115°C）。
- watchdog/reboot：验证 warm reboot 是否还失败；若仍失败，设为已知限制（禁用 SSH reboot，改断电），不为此牺牲启动稳定性。
- timer：确认 `sp804` 为 clocksource/clockevent、无 `dummy_timer is not functional`。
- pstore：确认冷启动后 ramoops 能否保留日志；若做诊断，可临时加 netconsole，但注意 `docs/054` 中 netconsole 曾参与死机，需隔离测试。

**完成标准**：连续 24 小时无掉线；thermal 有读数；warm reboot 行为有明确结论（可用或列为限制）。

### P4 — 深度功能（依赖 P0–P2 全绿）

1. 视频硬解/编码实测（`ffmpeg -vaapi_device` 或 V4L2 M2M；6.3 软解 1080p30 仅 ~0.7x）。
2. 音频链路：HDMI/AIAO 输出、音量控制。
3. GPU 桌面：kmsro/DRI3 真正走 lima，glamor 加速的 XFCE；严禁再引入用户态写显存的路径。

**完成标准**：有可复现的播放/编码测试命令与帧率数据；声卡可播放；GPU 渲染由 `glxinfo` 证明。

## 3. 每轮迭代的固定流程

1. 在 `patches/histb/` 按 quilt 规则新增/刷新补丁（`--fuzz=0`，编号与 `series` 同步）。
2. 本地轻量校验：`quilt push -a`、`git apply --check`、`bash -n`、必要时 `dtc`；**不出整包、不直接写真机**。
3. 同步更新 config fragment 与 `scripts/build-kernel.sh` 断言，同一 commit。
4. `workflow_dispatch` 触发 CI（必要时用 `extra_cmdline` 传参，注意它必须进 p2 runtime env）。
5. 下载 release 到项目内 `TMP/ci-download/`，核对 `SHA256SUMS.txt`。
6. 刷机 → 记录 L0/L1/L2 与原始日志 → 写入验证日志 → 回到 1。

## 4. 风险与已知限制

- **7.4 真机空白**：所有"已验证"结论都来自 6.3 同款驱动；7.4 必须在 P0 重新确认，不能直接继承。
- **硬锁死**：GPU 渲染模式下盒子曾在 uptime 128–165s 掉线；pstore 没抓到 panic，怀疑 CPU 硬锁而非内核 panic。排查时优先保留可恢复手段（断电、recovery-flasher 包）。
- **CMA 是生死线**：16MiB 会导致 X 回退和硬锁；160MiB 必须进 p2 env，不能只写进 DTB。
- **warm reboot**：6.3 上失败，7.4 补丁可能改变行为，需专测。
- **仓库卫生**：旧脚本/旧文档描述的仍是 6.3 或 stock 16 分区路线；以本计划和 `README.md` 为准，其余标记"历史/诊断用途"，不擅自删除。
